# FR-12 動作状態管理（待機 ⇔ 動作中）

## 内容

アプリからの動作開始・停止コマンドに従い、モータ駆動を含む動作状態（待機・動作中・終端）を管理する。起動直後は待機とし、明示的な開始コマンドなしにモータを駆動しない。

## 仕様

- 動作状態は `standby`（待機）・`operating`（動作中）・`fault`（終端）の 3 状態とし、`STATUS`/`EVT_STATUS` の `op_state` でアプリへ報告する。
- `standby` はモータ無駆動の待機状態とする。推定・オドメトリ・リンク処理は継続し、キャリブレーション（FR-13）とセットアップ系リクエストを受理する。モータのデューティ・トルク出力は常時ゼロとし、`standby` 中は制御器の mode 0（終端）ラッチを適用しない。
- `operating` は従来どおりの動作（FR-01〜FR-07、FR-09〜FR-11）を行う。イネーブル経路は `!estop && imu_ok` に加えて `operating` 状態を条件とする。
- `START_OPERATION` は以下がすべて成立するときのみ受理（`result=0`）する: `imu_ok`・E-Stop 解除・非 `fault`・バイアス資格（qualified）成立・姿勢が `start_tilt` 未満。`start_tilt`（既定 5 deg）は Simulink の傾斜起動検証（輪–球摩擦 μ=0.4 反映の現行構成でリカバリ窓 ~5 deg・5 deg 起步で ~0.5 s 起立成功）に基づく開始許容角で、転倒終端を示す `fallen_tilt`（35 deg）とは別パラメータとする。不成立時は `NOT_READY`/`REJECTED_STATE` を返す。受理時に制御器の一時状態（積分・フィルタ・ラッチ・ランプ時計）を初期化し、`startup_torque_ramp_time`（0.4 s）でトルクを立ち上げる。さらに `standby` 中は推定・オドメトリが走り続けるため、受理→最初の制御ティックの前に推定器の動的状態（速度・ボール回転・相対位置・姿勢）をリセットして再シードし、オドメトリは `SET_POSE`/`RESET_ODOMETRY` で宣言した位置・向きを現在の生値へ再適用する（待機中に手で車体を動かす等で蓄積した推定ドリフトを動作開始へ持ち込まない）。推定器は受理判定で確認済みのバイアス資格と学習済みバイアス・yaw を保持する。
- `STOP_OPERATION` は常時受理し、即時に `standby` へ遷移する（トルク即遮断。ランプダウンは行わない）。`fault` 状態からも受理し、故障リセットとして `standby` へ復帰する。
- `fault` は従来の mode 0 終端に対応し、`operating` 中のイネーブル喪失・転倒（`fallen_tilt` 超過）・IMU 異常で遷移する。復帰は `STOP_OPERATION`（または `bb stop`）で `standby` へ戻し、再開始可否は `START_OPERATION` の受理判定が担う。`standby` 中の傾き・E-Stop は `fault` へ遷移させず、`START_OPERATION` の拒否条件として残る。
- `standby` 中の運動系リクエスト（`SET_VELOCITY`・`SET_POSE_TARGET`・`SET_CONTROL_MODE`）は `REJECTED_STATE` で拒否する。
- リンク断絶（UART アイドル 1 s 超過）は `operating` 中も `standby` へ遷移させず、運動指令ゼロ＋その場保持を継続する（転倒防止）。購読・モードのリセットは従来どおりとする。
- `command_profile` の内部プロファイル駆動は `operating` 中のみ有効とする。リンク未確立時にアプリなしで動作を開始するため、`bb start`/`bb stop` shell コマンドを提供する。

## 根拠

運用要求（アプリからの動作開始・停止）。現行は起動直後からモータが駆動するため、キャリブレーションや所定位置への配置が完了する前に動き得る。
