# FR-01 BLE 透過 UART

## 内容

ホスト UART（UART0）と BLE 接続の間でバイトストリームを双方向に透過する。アプリ側からは Nordic UART Service（NUS）相当の BLE ペリフェラルとして見える。

## 仕様

- GATT サービスは NUS 互換 UUID を用いる。既存の BLE クライアント（nRF Connect / nRF Toolbox）やライブラリで検証できることが目的。
  - サービス: `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`
  - RX 特性（アプリ→モジュール、Write）: `6E400002-B5A3-F393-E0A9-E50E24DCCA9E`
  - TX 特性（モジュール→アプリ、Notify）: `6E400003-B5A3-F393-E0A9-E50E24DCCA9E`
- UART0 RX で受け取ったバイト列は TX 特性の Notification として送出する。1 通知のペイロード上限は接続中の ATT MTU（実効 MTU-3）に従い、これを超える受信分は分割して送出する。
- RX 特性への Write で受け取ったバイト列は UART0 TX へ送出する。順序は受信順を維持する。
- リンク未接続・Notification 未許可（CCC 未設定）の間、UART→BLE 方向のデータはキューせず破棄する。UART→BLE 方向が一時的に送出不能な場合の扱いは `link` の送出 API の成否に委ね、破棄バイト数は統計として記録する。
- 同時接続は 1 セントラルのみとする（`CONFIG_BT_MAX_CONN=1`）。
- デバイス名は `uwc-esp32c6` とし、Advertising に NUS サービス UUID を含める。

## 根拠

専用コントローラ兼ログ取得アプリとの無線透過リンクが目的。NUS 互換とすることで独自プロトコル実装前でも既製ツールで疎通検証できる。
