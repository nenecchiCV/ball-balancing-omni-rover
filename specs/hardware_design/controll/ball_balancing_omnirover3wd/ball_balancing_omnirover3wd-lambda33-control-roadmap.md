# λ=33° 体制における制御改善計画

前提: 車輪接触緯度 33°・案B内向きモーター格納を採用済み（cycle 完走 0.35°・hold 0.15°・yaw 完走・CG-20mm 保持）。本計画は (a) 高緯度時代の回避策の棚卸し・機能削減、(b) 指令速度域の拡大、(c) 並進/ヨー同時実行の3本立て。

## 1. 機能監査 — 本質機構の抽出

**判定基準**: 単一シードのシミュレーションで差が出なくても、センサノイズ・外力・外乱・モデル誤差を吸収する機能は維持する。削除対象は「無効（ゲイン0・フラグoff）のまま残っているデッドパス」に限定する — 無効の機能は耐性にも寄与しない。

### 1.1 維持 — 本質機構

| 機能 | 役割 | 判定根拠 |
|---|---|---|
| `stopFollowGain=0.75` | 停止窓のボール追従 | λ33 で無効化 → **16.2s転倒**（接触ドラッグへの本質対策） |
| `yawDampingGain=0.30` | 移動中のヨードリフト減衰 | ボール z スピン混入によるヘディングドリフトを吸収（実機の摩擦不均一・外乱耐性） |
| `ballYawGain=0.12` + 上限 | ボール鉛直スピンポンプ抑制 | オムニ運動学のスピン混入を吸収（物理起因は緯度不変） |
| `staticLeanAdapt` | 静的リーン/CGオフセット学習 | 実機の重心誤差・搭載物偏心を吸収する主要機能 |
| `stillVelocityDrain` + holdTime | 静止時速度ドレイン | エンコーダ量子化フリッカー（センサ物理、緯度不変） |
| `velocityAnchor` + minSpeed | 加速度積分バイアス排出 | 推定器バイアス蓄積の吸収 |
| `accelNormGate` / `accelHorizontalGate` | 加速度ゲート | 動加速度による誤姿勢補正の遮断（外乱耐性） |
| `truthFeedbackEnabled` / `truthDelaySteps` | 真値診断フック | 無効時コストゼロのデバッグ手段 |

### 1.2 維持（保険機能）— 名義軌道では不発動だが外乱条件を吸収

| 機能 | 評価 |
|---|---|
| `accelRelPosGuardGain=12`（偏心ガード） | λ33 の名義 cycle では不要（off 0.304° vs on 0.349°、シードばらつき程度）。ただし対象条件「偏心状態への移動脚突入」は実機では外乱・段差・推定誤差で普通に発生し、λ33 でも物理的には脱輪の可能性が残る → **保険として維持**。発動回数をログ化して実機での使用率を観測するのが望ましい |

## 2. 指令速度域の拡大

### 現状の指令上限（λ33）

| 量 | 値 |
|---|---:|
| モーター速度由来の理論上限 `Rw·ω_max/sinλ` | 0.808 m/s |
| 現在の目標指令 `commandSpeedFraction=0.5` | 0.404 m/s |
| cycle 指令速度 | 0.12 m/s |
| 高緯度時代に観測された接触壁 | ~0.2 m/s（λ65 の条件。λ33 では未再測定） |

### 作業項目

1. **速度限界の再特定（最重要）**: `commandSpeedFraction` 掃引（0.5→0.65→0.8、または定速 stepX の速度掃引 0.12→0.306→0.5 m/s）で、λ33 ではどの機構が先に限界になるかを分類する。想定候補:
   - 減速距離の伸長（停止窓での残留運動量→ボール先行→脱輪、偏心ガードの出番）
   - モーター連続トルク飽和（加減速時）
   - 接触包絡（輪荷重抜け）
   - 推定器の速度ラグ
2. **指令プロファイルの見直し**: 速度が上がると同じ 4s 停止窓では減速が間に合わない可能性。`cycleStopDuration` の速度適応化 or `maxPlanarAcceleration` の引き上げ可否（トラクション加速度上限との比較）
3. **偏心ガードの役割変化**: 高速化で停止窓残留速度が増える → ガードが保険から実用機能へ変わる可能性。高速域でゲイン再掃引

### M2 結果 — 定速掃引による限界機構の分類

定速指令掃引（stepX 相当、20 s/条件）を 0.15–0.50 m/s で実施。

| 指令 [m/s] | 実速度中央値 [m/s] | 実速度最大 [m/s] | 推定速度中央値 | 転倒 | 輪荷重最小 [N] |
|---:|---:|---:|---:|:--:|---:|
| 0.15 | 0.007 | 0.028 | 0.011 | なし | ≈0.70 |
| 0.25 | 0.016 | 0.109 | 0.019 | なし | ≈0.70 |
| 0.306 | 0.015 | 0.038 | 0.029 | なし | ≈0.70 |
| 0.306（推進2倍） | 0.016 | 0.040 | 0.055 | なし | ≈0.70 |
| 0.40 | 0.016 | 0.048 | 0.051 | なし | ≈0.70 |
| 0.50 | 0.016 | 0.039 | 0.054 | なし | ≈0.70 |

**分類: 推進平衡ストール（追従ストール）** — 指令が速度ランプ上限（0.03 m/s²）で立ち上がっても、実系は ~0.01–0.05 m/s のクリープ平衡に留まり、指令 0.5 m/s まで転倒・脱輪・デューティ飽和なしで追従しない。

否定された機構:
- **接触壁/接触破壊**: 全条件で転倒なし（maxTilt ≤ 0.01 rad）
- **輪荷重抜け**: Nmin ≈ 0.70 N（名義 ~3.9 N の 18%、抜けていない）
- **デューティ/電流飽和**: duty 非飽和、トルクは牽引上限 0.078 N·m 未満
- **推定器ラグ**: 推定-真値 rms 誤差 ~0.006 m/s（推定器は追随）

残る候補（内部飽和、物理資源ではない）:
- 推進トルク上限を 0.045→0.09 N·m・ゲイン 0.02→0.06 に倍増しても実速度不変 → **推進チャネルのトルク予算では限界でない**
- リーン指令上限 `leanSetpointLimit=0.009` rad → 定常の重力加速上限 ~0.09 m/s²、および速度誤差→リーン経路の権限が飽和する可能性
- 輪速オブザーバ（`wheelRateObserverDriveGain=306`）がトルク予測で輪速推定を嵩上げし、推進誤差 `rateError` を縮小させている可能性
- `stopFollowGain` 追従ブレーキとの相互作用

後続: ボールが転がり続ける定常条件（転がり抵抗 vs リーン権限）の解析、必要なら `leanSetpointLimit`・速度積分権限・オブザーバ予測ゲインの切り分け掃引。

### M2 追試 — ストールの根本原因（確定）

切り分け掃引（cmd=0.306 m/s・20 s・v12 モデル）:

| 条件 | 実速度中央値 | 判定 |
|---|---:|---|
| ベースライン | 0.017 m/s | — |
| `leanSetpointLimit` 0.009→0.02 | 0.016 m/s | リーン上限は非拘束（`velocityLeanGain·err ≈ 0.075 < cap 0.088` でそもそも cap 未到達） |
| 輪速オブザーバ OFF | **0.044 m/s（2.6×）** | **主犯** |
| `driveGain` 306→30 | 0.030 m/s | 部分回復 |
| `driveGain` 306→5 | 0.023 m/s | 部分回復 |
| `observerGain` 0.15→0.5 | 0.016 m/s | 計測重み強化は無効 |

**機構**: `wheelRateObserverDriveGain=306` は無負荷輪の τ→ω̇ 応答をモデル化するが、ボール接触荷重下の実応答は ~100 倍遅い（実測 dω/dt≈0.1 rad/s² @ τ≈0.045 N·m → 実効ゲイン ~2–5）。予測項が推定輪速を実測より大幅に嵩上げし、(a) 推進誤差 `rateError` が縮退して推進トルクが cap に達せず、(b) `slipRate = filtered − kinematic` が不感帯を超えてスリップダンパが実在しないスリップに制動を掛け続ける。同一 duty でもトルク配分が制動→駆動へ転換し 2.6 倍の速度回復が起きた。

**対処**: `wheelRateObserverEnabled=false` を既定に変更（オブザーバの残存価値 = 静止時 flicker→tilt-rate ノイズポンプ抑制は、現動作点では非致命 — cycle 無効化でも 49.5 s 完走・tilt 0.84° で G01 内）。コード経路は flicker 対策の研究用に残置。**残存する ~0.05 m/s の頭打ちは別機構**（ヘッドルーム分配・シャフト摩擦との力平衡 — 推進トルク ~0.045 N·m/wheel でさらに上を目指すには推進権限・摩擦モデルの再検討が必要）。

cycle（49.5 s ヨー窓なし）でのオブザーバ設定比較 — 既定決定の根拠:

| 設定 | 実速度中央値 | maxTilt | estVelErr（G07 ≤0.02） | 採点 |
|---|---:|---:|---:|---:|
| driveGain=306（旧既定） | 0.017 m/s | 0.375° | 0.016 ✓ | 7/8 |
| driveGain=30 | 0.030 m/s | 0.661° | 0.024 ✗ | ≈6/8 |
| observer OFF（新既定） | 0.044 m/s | 0.838° | 0.025 ✗ | 6/8 |

注意: driveGain=306 の G07 合格は**運動自体を抑制した退化パス** — 実速度との比で見ると推定誤差率は 0.016/0.017≈94% であり、OFF の 0.025/0.044≈57% より悪い。実際に動かした分だけ絶対誤差が増える構造で、OFF の方が推定精度は実質良好。driveGain=30 は予測ゲインが依然 ~10 倍過大で G07 も回復しない中途半端な設定のため採用せず、**OFF を既定とする**（tilt 0.84° は G01 ≤1° を満たす）。

fastsim 側も `wheelRateObserverEnabled=False` に整合済み。

## 3. 並進 + ヨー回転の同時実行

### 予算の定式化

各輪の要求レートは `|ω_i| = |sinλ·(v·t_i)/Rw + (R_ch·ψ̇)/Rw + バランス項|`。モーター速度上限とトラクションコーンを共用するため、**(v, ψ̇) の結合実現領域**を先に算出する:

- 速度面: `|v|·sinλ + R_ch·|ψ̇| ≲ ω_max·Rw`（全輪で成立する凸領域）
- トルク面: ヨー成分はコモンモード（3輪同符号）として牽引トルクと加算 → トラクションコーンとの非干涉を確認

### 作業項目

1. **結合リミッタ設計**: `command.velocityWorld` と `command.yawRate` の組が実現領域を外れたときに同時スケーリングするリミッタ（現状は各成分の個別クリップのみと想定 — 実装確認から）
2. **ベンチマークシナリオ追加 `moveYaw`**: 例: v=0.15 m/s + ψ̇=0.4 rad/s の円弧走行 10s、判定は輪荷重抜けなし・速度/ヨーレート追従誤差・tilt
3. **ヨーダンパとの整合**: `yawDampingGain` は移動中のドリフト抑制だが、指令ヨー中は逆に干渉する可能性（ダンパが指令回転を阻害）→ 指令ヨー時のダンパゲート処理を確認
4. **spin brake との整合**: 指令ヨー中のボール z スピンは「正常な回転」なので brake が逆向きに働く可能性 → 指令成分の差し引き or ゲートを確認

### 計測されたヨー回転包絡（M4 回帰で確定）

持続ヨーは**総回転角 ~0.4-0.6 rad が物理限界**。機構は制御コードの既知注記どおり — コモンモード輪トルクがボール自由 z スピンをポンプし、蓄積後に輪の法線力が偏って脱輪・転倒。v9（外向き）/v12（内向き実測）両質量モデルで再現し、以下の全てでも不変:

- `ballYawGain` 0→0.48、`ballYawTorqueLimit` 0.025→0.10
- LQI ヨー列ゲイン ×1→×10（転倒時刻は +0.5 s 伸びるのみ）
- エンコーダ分解能 ×100（量子化フリッカー排除しても同時刻転倒）
- `wheelRateFeedbackEnabled`/`slipDampingGain`/`propulsionGain` 個別無効化
- `yawGate.maxTilt` 0.02→0.5（ゲート解除も転倒時刻不変）

実測の生存/転倒境界（静止発進、三角台形指令）:

| ヨー指令 | 総回転角 | 結果 |
|---|---|---|
| 1.0 s @ 0.8 rad/s | ~0.4 rad | 完走（maxTilt 0.006 rad） |
| 1.5 s @ 0.4 rad/s | ~0.3 rad | 完走（maxTilt 0.004 rad） |
| 1.5 s @ 0.5 rad/s | ~0.375 rad | t≈5 s 転倒 |
| 1.5 s @ 0.8 rad/s | ~0.6 rad | 窓終了 ~1 s 後に転倒 |
| 連続 0.2/0.3/0.5 rad/s | — | 2.6-3.4 s で転倒（レートにほぼ不感） |

ボール z スピンは転倒時に |oBz|~0.4-0.7 rad/s 程度で、従来の経験則 |oBz|~3.5 よりはるかに低い — λ33 ではスピン絶対値ではなく法線力再配分の蓄積がリミッタ。**ヨー制御にバースト上限（~0.4 rad/回・インターバルでスピン抜き）を課すこと**が実運用の条件。

**cycle 内内ヨー窓はさらに厳しい**: 上表の静止発進単発バーストは 0.3-0.4 rad で生存するが、cycle の停止窓に埋め込んだ同量バーストは後続移動相で転倒する（v12 実測モデル）:

| ヨー窓（三角、ピーク→面積） | cycle 転倒時刻 | 転倒箇所 |
|---|---:|---|
| 0.8 rad/s × 1.5 s（~0.6 rad） | t=16.14 s | ヨー窓（13.5–15.0）終了 ~1 s 後 |
| 0.8 rad/s × 1.0 s（~0.4 rad） | t=27.46 s | cycle2 減速コーナー（残滓スピン ±0.1 が次減速を不安定化） |
| 0.4 rad/s × 1.5 s（~0.3 rad） | t=17.31 s | ヨー窓終了 ~2 s 後 |
| 0（`profileYawRate=0`） | **完走 49.5 s・maxTilt 0.38°** | — |

輪速オブザーバ無効化（新既定）後の再掃引でも結論は不変 — 窓位置を停止相先頭へ移して整定時間を稼いでも cycle 内ヨーは転倒する（全て 49.5 s シミュレーション・v12・obs-off）:

| ヨー窓設定 | cycle 転倒時刻 |
|---|---:|
| 0.4 rad/s × 1.5 s @ delay 1.0（~0.3 rad、旧条件再現） | t=22.83 s |
| 0.4 rad/s × 1.0 s @ delay 0（~0.2 rad） | t=27.46 s（cycle2 減速） |
| 0.4 rad/s × 1.5 s @ delay 0 + stop 6 s（~0.3 rad） | t=17.27 s |

対策として `cycleYawEvery` を追加 — ヨー窓を N 周期ごとに 1 回へ間引き、バースト間に完全な移動/停止周期を挟んで残滓スピンを減衰させる（MATLAB・fastsim 共通実装）。

最終掃引（49.5 s・v12・obs-off、全て delay=0 = 停止相先頭）:

| 窓 | 頻度 | 結果 |
|---|---|---|
| 0.4×1.0s（0.2 rad） | 毎周期 | t=27.46 転倒（1 バーストで致命） |
| 0.4×1.0s（0.2 rad） | 隔周期 | t=27.46 転倒（同上 — 最初のバーストが致命） |
| 0.2×1.5s（0.15 rad） | 毎周期 | t=23.2 転倒 |
| 0.2×1.5s（0.15 rad） | 隔周期 | t=23.2 転倒 |
| 0.4×0.5s（0.1 rad） | 毎周期 | t=46.01 転倒（cycle3 入口） |
| 0.2×1.0s（0.1 rad） | 毎周期 | t=48.93 転倒（最終盤） |
| 0.2×1.0s（0.1 rad）毎 + stop 6s | 毎周期 | t=32.89 転倒（整定延長は無効） |
| **0.2×1.0s（0.1 rad）** | **隔周期** | **完走 49.5 s・maxTilt 1.30°** |

**既定値を検証済み構成へ変更**: `cycleYawDelay=0`・`cycleYawDuration=1.0`・`cycleYawEvery=2`・`profileYawRate=0.2` — 移動/停止/回転（0.1 rad/回・停止窓ごとに 1 回）が全て繰り返し実行され完走する。バースト予算は「停止窓あたり」ではなく「**移動+停止 1 周期あたり ~0.1 rad**」が包絡 — 1 バーストの残滓が次の移動脚減速コーナーを不安定化するため、頻度間引きが唯一の生存手段だった（整定時間延長・ヨー窓位置移動・窓形状変更は全て無効）。

因果は確定的: ヨー窓を外すだけで v12 質量モデルの cycle は完走し、並進耐久・接触包絡は健全。**既定プロファイルは検証済みの間引きヨー構成へ変更済み**（`cycleYawEvery=2`・`cycleYawDelay=0`・`cycleYawDuration=1.0`・`profileYawRate=0.2` — 停止窓 2 回ごとに ~0.1 rad バースト）。移動・停止・回転の連続繰り返しが 49.5 s 完走・maxTilt 1.295°・転倒なしを確認（`scratch_cycle(49.5,'m10_default')`、cmdYawMax=0.200）。採点の回帰比較性を保つため `ballbotBenchmark('cycle')` はヨー窓なしにピン留め（6/8・tilt 0.838°）。ヨー込み既定プロファイルの採点は 4/8 — 不達は G01 傾斜 1.295°・G06 推定傾斜誤差 0.53°・G02・G07 で全て閾値マージン系、転倒・脱輪・分離なし。

`ballbotRev1CommandProfile` に `command.yawPulseDuration` を追加: 非 cycle 経路のヨー指令を三角台形で打ち切る（0=従来挙動・既存シナリオとビット一致）。
